# NEOVEX — ONE CORE

Концептуальный интерактивный 3D-сайт компании Neovex по техническому заданию
«NEOVEX — ONE CORE».

Вся визуальная часть построена вокруг одного объекта — нейронной сферы. При
прокрутке пользователь не переходит между статичными секциями, а управляет
развитием одной непрерывной 3D-сцены: сфера деформируется, перестраивается и
переходит из одного состояния в другое.

## Запуск

```bash
npm install
npm run dev
```

Открыть http://localhost:3000

Прочие команды:

```bash
npm run build      # продакшен-сборка
npm start          # запуск собранного приложения
npm run typecheck  # проверка типов без сборки
```

## Как это устроено

### Прокрутка управляет сценой

```
Scroll → ScrollTrigger → scrollState.progress → sampleTimeline() → Three.js
```

- [`ScrollDriver`](src/components/ui/ScrollDriver.tsx) — единственное место, где
  страница разговаривает со сценой. ScrollTrigger отдаёт нормализованный
  прогресс документа.
- [`lib/store.ts`](src/lib/store.ts) — прогресс живёт вне React. Рендер-цикл
  читает его напрямую, а в React уходит только «дискретная» часть состояния
  (активная стадия, флаг перехода), чтобы 60 fps не упирались в перерисовку.
- [`lib/timeline.ts`](src/lib/timeline.ts) — прогресс переводится в состояние
  сцены: форма, плотность связей, активность, положение камеры, слои AR/UI/робота.
  Ключевые кадры стоят **в центрах** состояний: в середине состояния сцена
  «отстоялась» и текст читается, а вся деформация происходит на стыках.
- [`lib/frame.ts`](src/lib/frame.ts) — один расчёт состояния на кадр. Камера,
  ядро и постобработка читают один и тот же результат, поэтому порядок подписок
  `useFrame` не влияет ни на что.

Высоту документа задаёт отдельная полоса: по экрану на каждое из семи состояний
плюс экран на возврат к исходной сфере. Тексты живут в закреплённом слое и
переключаются строго по прогрессу — иначе заголовок неизбежно расходится со
своим состоянием сцены.

### Один объект, четыре формы

[`lib/shapes.ts`](src/lib/shapes.ts) строит четыре облака точек одинаковой длины:

| # | Форма | Состояние |
| --- | --- | --- |
| 0 | Нейронная сфера | 01 HERO, 02 AI |
| 1 | Дом с мебелью | 03 3D, 04 AR, 05 VR |
| 2 | Абстрактные UI-панели | 06 SOFTWARE |
| 3 | Робот из скруглённых деталей | 07 ROBOTICS |

Ключевой момент: все формы — это **непрерывные отображения исходной сферы**.
У частицы берётся её направление (и развёртка `u`, `v`), и по нему считается
позиция в каждой форме: проекция на коробку стен дома, ячейка развёртки 3×2
для панелей, атлас деталей для робота.

Поэтому соседи на сфере остаются соседями во всех состояниях — нейронные связи
не превращаются в хаос линий, а силуэт новой формы читается сразу. Морфинг
сводится к интерполяции двух атрибутов в вершинном шейдере, без пересчёта
геометрии на CPU.

### Дом проходит через три состояния

Состояния 03, 04 и 05 показывают **один и тот же дом**. Разница только в
масштабе и положении камеры — это и есть сюжет:

- **03 3D** — дом целиком, камера близко и под углом: видны крыша с трубой,
  окна и внутренняя планировка сквозь стены. Модель медленно вращается,
  показывая объём.
- **04 AR** — дом сжат до `coreScale` 0.2 и парит над раскрытой ладонью
  человека. Человек здесь не из точек: это сплошная модель из скруглённых
  примитивов со своим светом ([`FigureLayer`](src/components/scene/FigureLayer.tsx)).
  Контраст «настоящая фигура — виртуальная модель в руке» и есть смысл кадра.
- **05 VR** — тот же дом вырастает до натуральной величины, камера входит
  внутрь, а человек разбирается на точки и оказывается в комнате вместе со
  зрителем. Теперь виртуально всё, включая наблюдаемого.

Дом ([`lib/house.ts`](src/lib/house.ts)) строится проекцией направления на
коробку стен: непрерывное отображение, поэтому связи рисуют каркас, а не
паутину поперёк комнаты. Сверху накладываются двускатная крыша с трубой, дверь
и окна (точки внутри проёма уходят на его рамку) и мебель — стол, кровать,
шкаф, диван: точки пола внутри их следа поднимаются на объём.

Одних точек для комнаты не хватает: изнутри ближняя и дальняя стены
накладываются и пространство теряет план. Поэтому есть
[`HouseFrame`](src/components/scene/HouseFrame.tsx) — явные рёбра периметра,
угловых стоек, конька, проёмов и мебели. Тот же приём вытягивает состояние
SOFTWARE и робота.

### Фигуры

Человек и робот описаны одним списком скруглённых примитивов
([`lib/figures.ts`](src/lib/figures.ts)) — эллипсоидов и капсул. Из одного
описания получается три вещи: меши для сплошной фигуры, облако точек через
развёртку атласа и проволочный каркас сечений. Скруглённые формы здесь
принципиальны: точками на гранях параллелепипедов силуэт не читается.

Робот собран по образцу дружелюбной модели: круглая голова с экраном вместо
лица (текстура рисуется на канве), боковые модули, поднятая в приветствии рука.
На последней трети сборки включаются лицо, эмблема на груди, подсветка суставов
и опорная сетка.

### Связи

[`lib/connections.ts`](src/lib/connections.ts) ищет пары соседей один раз, на
исходной сфере, через хеш-сетку. Сеть строится из двух типов связей:

- **короткие** — между соседними узлами, дают плотную ткань;
- **длинные хорды** через объём — именно они читаются как пересекающиеся линии
  внутри сферы. В собранных формах хорды гасятся, иначе они забивают силуэт.

У каждой связи свой порог видимости. Параметр `links` в timeline — это и есть
«плотность сети»: в состоянии AI она доходит до единицы, и сеть зажигает все
дополнительные соединения.

### Glitch-эффект текста

[`GlitchText`](src/components/ui/GlitchText.tsx) совмещает два источника помех:

1. **появление блока** — посимвольная сборка текста из мусорных глифов;
2. **состояние сцены** — интенсивность берётся из того же значения перехода,
   что и деформация сферы.

То же значение управляет RGB-сдвигом в постобработке, поэтому помехи в 3D и в
типографике случаются одновременно. После стабилизации новой формы текст
становится чистым.

### Производительность

[`lib/quality.ts`](src/lib/quality.ts) определяет тир устройства один раз при
загрузке и раздаёт бюджеты: количество частиц (2 600 / 5 200 / 9 000), связей,
фоновой пыли, ограничение `devicePixelRatio` и включение постобработки. При
`prefers-reduced-motion` берётся низкий тир, glitch-анимации отключаются.

Камера кадрируется под пропорции экрана: у каждого состояния заданы полуразмеры
того, что обязано поместиться в кадр, и на вертикальном экране камера отъезжает
ровно настолько, насколько нужно. На портретных экранах вид дополнительно
опускается, чтобы объект ушёл в верхнюю половину и не спорил с текстом.

## Структура

```
src/
├── app/                     layout, страница, глобальные стили
├── components/
│   ├── scene/               3D: канвас, ядро, камера, слои состояний
│   │   └── shaders/         GLSL: шум, морфинг, частицы, связи, фигура
│   ├── sections/            текстовые блоки состояний
│   └── ui/                  навигация, прогресс, glitch-текст, прелоадер
└── lib/                     прогресс, timeline, формы, дом, фигуры, связи, качество
```
